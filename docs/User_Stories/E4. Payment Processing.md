### E4. Payment Processing

#### US-16 Pay a bill from the wallet (FR-9) · Must
As a customer, I want to pay a bill from my wallet so that I don't queue at the biller's office.
- **Given** an inquiry result and enough available balance, **when** I pay, **then** the payment is created as Initiated, the fraud checks pass, the total is held (FundsHeld), the biller is called (SentToBiller), and on confirmation the payment is Completed.
- **Given** an available balance below the total, **when** I pay, **then** the payment is Rejected with a clear reason and no money is held.
- **Given** an amount outside 5 to 10,000 EGP, or a disabled biller, **when** I pay, **then** the payment is Rejected with a clear reason.
- **Given** a payment, **when** I check it, **then** I see its current state and reference.

#### US-17 Return the original result for a repeated idempotency key (FR-10, §2.7 case 1) · Must
As a customer, I want a repeated request to be safe so that a slow network never charges me twice.
- **Given** a payment request with idempotency key K from account A already processed, **when** account A sends the same key again, **then** the first result is returned and there is no second hold, charge, or biller call.
- **Given** the first request is still in progress, **when** the same key arrives from the same account, **then** the current state is returned.
- **Given** key K reused by the same account with a different amount or biller, **when** it is sent, **then** it is rejected with a clear reason.
- **Given** two different accounts send the same key string, **when** both are processed, **then** each is treated as its own request and neither receives the other's result (D-15).
- **Given** an agent pays on behalf of a customer, **when** the key is checked, **then** it belongs to the agent's account.
- **Given** two identical requests from the same account at the same moment, **when** both are processed, **then** only one payment is created, because the database enforces one payment per account and key.

#### US-18 Allow only the payment lifecycle transitions (FR-11) · Must
As the system owner, I want only valid state changes so that a payment can never reach an impossible state.
- **Given** a payment in any state, **when** a transition is requested, **then** only the §2.5 transitions are allowed (Initiated to FundsHeld or Rejected, FundsHeld to SentToBiller, SentToBiller to Completed, Failed or Unknown, Unknown to Completed or Failed, Failed to Refunded).
- **Given** a payment in a final state (Completed, Rejected, Refunded), **when** any change is requested, **then** it is refused and logged.
- **Given** a payment in Unknown, **when** the system looks for refunds, **then** it is never refunded automatically.

#### US-19 Hold funds before the biller call and release them on failure (FR-12) · Must
As a customer, I want my money reserved first and returned if the payment fails so that I never lose money for an unpaid bill.
- **Given** a payment passes the checks, **when** it starts, **then** the total moves from available to held before the biller is called.
- **Given** the biller refuses, **when** the payment becomes Failed, **then** the full hold is released to my available balance and the payment becomes Refunded.
- **Given** the biller does not answer, **when** the payment becomes Unknown, **then** the hold stays and I am told it is being processed.
- **Given** the biller confirms, **when** the payment is Completed, **then** the hold becomes a final charge.

#### US-20 Reject one of two simultaneous payments when the balance covers only one (§2.7 case 4) · Must
As a customer, I want my balance protected so that it never goes negative.
- **Given** 400 EGP available and two simultaneous payments of 352.50 EGP, **when** both arrive at the same moment, **then** one is FundsHeld and the other is Rejected for insufficient funds.
- **Given** any number of concurrent payments, **when** they finish, **then** the wallet balance is never negative and the ledger sum matches the balance.

#### US-21 Agent pays on behalf of a customer (FR-17) · Should
As an agent, I want to pay a bill for a customer at my terminal so that people without the app can still pay.
- **Given** an agent and a customer's wallet with enough funds, **when** the agent pays, **then** the payment follows the normal lifecycle and records the agent on the payment.
- **Given** an agent payment completes, **when** it reaches Completed, **then** the commission rule of US-14 applies.
- **Given** an account that is not an agent, **when** it tries to pay on behalf of another customer, **then** it is rejected.
