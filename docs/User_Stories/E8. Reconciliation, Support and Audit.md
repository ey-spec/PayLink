### E8. Reconciliation, Support and Audit

#### US-33 Produce a daily reconciliation report from a settlement file (FR-26) · Should (treated as Must, D-5)
As a support employee, I want PayLink's payments compared with each biller's settlement file so that differences are found every day.
- **Given** a settlement file for a biller and a day, **when** reconciliation runs, **then** a report lists each payment as Matched, Missing in PayLink, Missing in the file, or Amount different, matched by payment reference.
- **Given** a payment in Unknown that the file lists as paid, **when** reconciliation runs, **then** the payment becomes Completed; **given** the file does not list it, **then** it becomes Failed and is then Refunded (§2.5).
- **Given** the same settlement file is processed twice, **when** it runs again, **then** nothing changes a second time and the report is the same.
- **Given** a malformed or missing file, **when** reconciliation runs, **then** it stops with a clear error and changes no payment.

#### US-34 Flag a payment that the settlement file lists but PayLink has as Failed (§2.7 case 7) · Must (D-5)
As a support employee, I want this difference flagged for review so that no one is paid twice or left unpaid by mistake.
- **Given** the file lists a payment that PayLink has as Failed, **when** reconciliation runs, **then** the report flags it as a difference for support to review.
- **Given** a flagged difference, **when** reconciliation finishes, **then** the payment state and the wallet are not changed automatically.
- **Given** a flagged difference, **when** support opens the report, **then** they see the reference, both amounts, both states, and the date.

#### US-35 Support searches a payment by reference and sees its history (FR-20) · Must
As a support employee, I want to find a payment by its reference so that I can answer a customer quickly.
- **Given** a valid reference, **when** I search, **then** I see the payment with its biller, amount, fee, total, current state, and agent if any.
- **Given** a payment, **when** I open it, **then** I see its full history: every state change, ledger entry, biller call, retry, and notification, with times.
- **Given** an unknown reference, **when** I search, **then** I see "not found" and no error.
- **Given** a user who is not support, **when** they try to search by reference, **then** the request is rejected.

#### US-36 Write an audit record for every money movement and admin action (FR-25) · Must
As a regulator and PayLink management, I want every money movement and admin action recorded so that we can prove who did what and why.
- **Given** any ledger entry (top-up, hold, release, charge, fee, commission), **when** it is written, **then** an audit record is written with who, when and why.
- **Given** an admin action (biller edit, fee or limit change, upgrade, block or unblock), **when** it happens, **then** an audit record is written with the old and new values.
- **Given** any audit record, **when** it is stored, **then** it cannot be edited or deleted.
- **Given** the audit log and the ledger, **when** they are compared, **then** 100% of ledger entries have a matching audit record (NFR-5).

#### US-37 Request a refund of a completed payment and support approves it (FR-27) · Could
As a customer, I want to request a refund of a completed payment so that a mistaken payment can be corrected.
- **Given** a Completed payment, **when** I request a refund with a reason, **then** a refund request is created as Pending.
- **Given** a Pending request, **when** support approves it, **then** the money is returned to my wallet through new ledger entries and an audit record shows who approved it and why.
- **Given** a Pending request, **when** support rejects it, **then** nothing changes and I am told the reason.
- **Given** a payment that is not Completed, or already refunded, **when** I request a refund, **then** the request is rejected.

#### US-38 Admin views daily totals (FR-28) · Could
As an admin, I want daily totals so that I can see how the business is doing.
- **Given** a day, **when** I open the totals, **then** I see the number and amount of payments, fees earned, commissions paid, and failures per biller.
- **Given** the ledger, **when** the totals are calculated, **then** they equal the sum of the matching ledger entries.
- **Given** a day with no payments, **when** I open the totals, **then** I see zeros and no error.
