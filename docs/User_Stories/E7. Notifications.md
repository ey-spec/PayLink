### E7. Notifications

#### US-31 Send SMS and push on completion and on failure (FR-22) · Must
As a customer, I want an SMS and a push message when my payment completes or fails so that I always know the result.
- **Given** a payment becomes Completed, **when** the event happens, **then** I receive an SMS and a push message with the biller, amount, fee and reference.
- **Given** a payment becomes Failed, **when** the event happens, **then** I receive an SMS and a push message with a clear reason (for example the mapped AquaCo reason).
- **Given** a message template for each outcome, **when** a notification is created, **then** the text is filled from the template and no message text is hard-coded in the payment code.
- **Given** a notification is sent, **when** it succeeds, **then** its status is recorded as Delivered with the time.

#### US-32 Retry a failed notification 3 times, then mark it undelivered (FR-23, §2.7 case 5) · Should (treated as Must, D-5)
As the system owner, I want failed messages retried so that a provider outage never affects the payment.
- **Given** the SMS provider is down when a payment completes, **when** the payment is processed, **then** the payment still ends Completed and its charge and ledger entries are not changed.
- **Given** an SMS fails, **when** the failure is detected, **then** it is retried 3 times, and if the retries also fail it is marked Undelivered.
- **Given** a retry succeeds, **when** it is sent, **then** the notification is marked Delivered and no further retries are made.
- **Given** a notification is Undelivered, **when** support looks at the payment, **then** the failed notification and its attempts are visible.
