### E3. Fees and Commissions

#### US-11 Calculate the fee by biller rule (FR-16) · Must
As a customer, I want the fee calculated by the correct rule so that I always know what PayLink charges.
- **Given** an electricity or water payment of any amount, **when** the fee is calculated, **then** it is 2.50 EGP.
- **Given** a mobile top-up of 200.00 EGP, **when** the fee is calculated, **then** it is 3.00 EGP (1.5%); **given** 50.00 EGP, **then** it is 1.00 EGP (the minimum).
- **Given** an internet payment of 200.00 EGP, **when** the fee is calculated, **then** it is 2.00 EGP; **given** 200.01 EGP, **then** it is 4.00 EGP.
- **Given** any calculation, **when** it is done, **then** money uses exact decimals and the rule values are read from configuration, not from code.

#### US-12 Apply a promotion period with a zero fee (FR-16) · Must
As PayLink management, I want a promotion period with no fee for one biller so that we can attract customers to it.
- **Given** a promotion for one biller with a start and end date, **when** a payment to that biller is made inside the period, **then** the fee is 0.00 EGP.
- **Given** a payment to that biller outside the period, or to any other biller, **when** the fee is calculated, **then** the normal rule applies.
- **Given** a promotion fee of 0, **when** an agent payment completes, **then** the agent commission is 0.00 EGP.

#### US-13 Run a bill inquiry and see amount, fee and total (FR-8) · Must
As a customer, I want to see the amount, fee and total before I pay so that there are no surprises.
- **Given** an electricity meter number, **when** I run an inquiry, **then** PayLink asks ElectroCo and shows the bill amount, the fee, and the total (for example 350.00 + 2.50 = 352.50 EGP).
- **Given** a biller that does not answer or returns an error, **when** I run an inquiry, **then** I see a clear message and no payment is created.
- **Given** an inquiry result, **when** I decide to pay, **then** the payment uses the amount and fee I was shown.

#### US-14 Credit the agent commission when a payment completes (FR-17) · Should
As an agent, I want to earn a commission on payments I make so that my work is rewarded.
- **Given** a payment made at an agent's terminal with a 2.50 EGP fee, **when** it reaches Completed, **then** 1.00 EGP (40% of the fee) is credited to the agent's wallet with a ledger entry.
- **Given** a payment that is Failed, Rejected or Unknown, **when** it is not Completed, **then** no commission is credited (D-2, D-9).
- **Given** a payment in Unknown that later becomes Completed (retry, callback or settlement file), **when** it reaches Completed, **then** the commission is credited at that moment, once.
- **Given** a completion event received more than once, **when** it is processed again, **then** the commission is not credited a second time.
- **Given** any attempt to add a second commission entry for the same payment, **when** it is written, **then** the database rejects it, because only one commission entry per payment is allowed (D-9).
- **Given** a payment made by the customer in the app, **when** it completes, **then** no commission is created.

#### US-15 Admin edits fee and limit values without redeploying (FR-24) · Should
As an admin, I want to change fees and limits so that PayLink can adapt without a new release.
- **Given** valid new values (for example a fee of 3.00 EGP), **when** I save them, **then** new payments use them immediately and an audit record shows who changed what, when, and the old and new values.
- **Given** a payment already in progress, **when** values change, **then** that payment keeps the fee and limits it started with.
- **Given** invalid values (negative, or a minimum above a maximum), **when** I save, **then** the change is rejected with a clear reason.
